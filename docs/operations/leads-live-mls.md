# Private live MLS research

The Spark worker attaches Playwright to the existing research Chrome on port 9223. It uses the normal Heartland/Clareity login and the read requests observed in the authenticated Remine browser. It does not expand account entitlements: the verified account currently has Remine Insights Plan access. Matrix, premium Remine features and unrestricted MLS exports are not implied.

Weekday sweeps at 6:30am and 7:15am America/Chicago search two Independence/Kansas City map areas for residential expired, withdrawn and canceled listings with a status date within 30 days. Each bounded sweep reads at most 100 results per area and verifies up to 35 property details, keeping at most 20. It rejects older listing matches when the property has a newer listing, mismatched identities/geography, missing details and unsupported statuses. This is a bounded research queue, not complete MLS coverage. Scores rank signals, not confirmed intent. MLS evidence is not a court, ownership or contact-permission investigation.

The ingest endpoint requires `SYNC_SECRET` and an active admin subscriber configured by `LEADS_DESK_SUBSCRIBER_ID`. Captures are stored only in that subscriber's private Lead/CrmActivity records, with no shared Listing/DossierResult writes. `/leads/tools/mls` and `/leads/mls/[id]` require the owner session and restrict reads to its subscriber. The latest sweep receipt exposes login/failure state. Only captures from the latest successful sweep, no older than 36 hours, enter the existing 8am top-five selection; previous drafts and follow-ups are excluded. A failed or empty sweep invalidates older captures for selection. The research library retains previous observations with their capture dates.

The worker creates and closes only its own browser tab. It stops on login/verification challenges and retries on the next schedule. Sign into the existing research browser on Spark to restore access when requested. No MFA bypass, contact sending, share-link creation, subscriptions, purchases or exports to external marketing systems are performed. MLS credentials, transient browser request headers and private remarks never enter logs or git. The local latest capture file is mode 600 under a mode 700 state directory.

Install `ops/spark/leads-mls.service` and `.timer` in the Spark user's systemd unit directory. The service working directory must point to this deployed checkout with Playwright, TypeScript and the tsx loader available. Create `/home/jelly/.config/tolley-mls/worker.env` mode 600 with `SYNC_SECRET`, `TOLLEY_API_URL=https://www.tolley.io` and the existing `MLS_USERNAME` / `MLS_PASSWORD` for ordinary session renewal. Credentials stay on Spark. Optional settings: `MLS_CDP_URL` and `MLS_DESK_STATE_DIR`. Reload systemd and enable the timer. `systemctl --user start leads-mls.service` performs a fresh publication; running the worker without `--publish` performs a read-only check. A process lock prevents overlaps. A busy research worker pauses this sweep.

Verify with `systemctl --user list-timers leads-mls.timer`, the latest service journal summary and the private research page. Disabling this timer stops collection; removing `LEADS_DESK_SUBSCRIBER_ID` also stops ingest and new weekday drops. Existing captures and drafts remain. Routine successful sweeps are quiet.

Validation uses `tests/leads-mls.ts` against the dedicated `tolley_weekday_test` PostgreSQL database, `tests/leads-weekday-drop.ts`, `tests/tagent-daily-use.mjs`, the build typecheck and a real authenticated browser sweep. No schema migration is needed.
